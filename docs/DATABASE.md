# Database

MySQL 5.7+ / MariaDB 10.3+, InnoDB, `utf8mb4_unicode_ci`. The schema is
created by the migrations in `database/migrations` (`php artisan migrate`).

Each MongoDB collection of the original backend became one table. Embedded
arrays and sub-documents (order items, addresses, category children,
product categories, coupon product lists) became child tables with foreign
keys, so the data is normalised and referential integrity is enforced.

## Conventions

| | |
|---|---|
| Primary keys | `id CHAR(24)`, a MongoDB-style ObjectId generated by the app. API responses expose it as `_id`. Ids imported from MongoDB are kept unchanged. Stored as ASCII (compact keys and indexes). |
| References | Same `CHAR(24)` type, with a foreign key unless noted. Child rows are deleted with their parent (`ON DELETE CASCADE`). |
| Dates | `DATETIME(3)` in UTC, millisecond precision (as MongoDB). API format: `2026-01-31T10:15:00.123Z`. |
| Money | `DECIMAL(12,2)`. |
| Lists of values | `JSON` columns (image file names, category names, related ids). |
| Status fields | `VARCHAR(20)`. Allowed values are validated by the app when records are created (`app/Models`), as the Mongoose schemas did. |

## Relationships

```
users 1─* user_addresses
users 1─* orders (by user_id, no FK)      orders 1─* order_items
                                          orders 1─* order_addresses
categories 1─* categories (parent_id)
categories *─* products    (category_product)
categories *─* gift_cards  (category_gift_card)
coupons 1─* coupon_products ─> products | gift_cards (polymorphic)
```
